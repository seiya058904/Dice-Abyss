你是负责《骰狱：无尽深渊》V5 的云端旗舰 AI，兼任高级独立游戏设计师、游戏程序架构师、数值策划和 QA 工程师。请以**随本任务上传的现有高特效桌面网页游戏项目 ZIP** 为基础继续开发，不要重建项目，不要把它替换为另一条“纯文字终端版”设计支线。

这轮的关键词是：**更多、更深、更稀有、更值得刷，但仍然简单、爽快、直观。**

游戏继续保持：**每层一条线、六个房间、以战斗为主 → 玩家手动掷骰 → 击杀后亲自开箱 → 获得装备 → 锻造/融合/升级天赋 → 深入无限地牢。** 不增加自动掷骰、复杂操控、多币种、手机优先布局或多分支地图。

V5 最重要的改变是：前 20～30 层保持 V4 已经好用的四档装备体验；进入 30、50、80 层等深度后，再陆续解锁**真正高于传说**的新稀有度。新增几十种房间也不能把日常战斗、商人、锻造和融合冲淡——必须有**按类别分层、按房间加权、同时保证核心遭遇稳定出现**的生成机制。

你有自主权决定数值、概率、技术实现和命名。本文给出**可验收的游戏目标与源码风险**，不是要求逐字照搬某个临时设计数字。

### 1.2 当前内容的真实规模

| 系统 | 源码事实 | 不是它所代表的东西 |
|---|---|---|
| 装备 | `648` 件；三类各 `216`：旧 `10主题 × 3轮廓 × 4品质 = 120`，额外 `6家族 × 4变种 × 4品质 = 96` | 不是 648 种互不相同的主动/被动规则 |
| 稀有度 | 仅 `普通 / 稀有 / 史诗 / 传说`，基础倍率 `1 / 1.7 / 2.9 / 5` | 目前不存在 30 层以上新档次的解锁 |

| 怪物与 Boss | 普通/特殊敌人共 `60` 个名称；`12` 位 Boss | 其中有共享性状、机制族，不是 72 套独立战斗 AI |

| 存档与发布 | 原子状态转换、独立 RNG、提交后播动画、V1–V3 到 V4 迁移、Pages 自动部署 | 不是可以随意更改持久化字段的临时原型 |

### 1.3 逐模块实际审计结论

**装备、掉落和稀有度：**

- [`src/equipment-content.js`](https://github.com/seiya058904/Dice-Abyss/blob/9acf0e0/src/equipment-content.js)：`RARITIES` 与 `CATALOG` 固定四品质；部分名称前缀数组也只有四项。升级八档时若只延长数组，会增量生成新物品，却不会自动有新机制和正确掉落规则。**保留所有旧 `catalogId` 和旧档次属性不变**，新增 ID 与新家族，不能重用旧 ID 赋予另一种属性。
- [`src/equipment.js`](https://github.com/seiya058904/Dice-Abyss/blob/9acf0e0/src/equipment.js)：`makeItem` 按角色等级上下约 2 级取基础掉落，特殊来源额外加级；`itemValue/itemStats` 按等级、品质、强化、效果计算。`validEquipment` 当前只允许 0～3 品质；`fusionPreview` 的材料价值常量也只有四档，传说保护有 `rarity===3` 条件。这些都必须扩展，且**传说和更高稀有度都默认进入珍贵材料保护范围**。
- [`src/engine.js`](https://github.com/seiya058904/Dice-Abyss/blob/9acf0e0/src/engine.js)：`rarityRoll` 对 Boss 固定返回品质 3，秘藏为品质 2/3，其他来源使用当前四档累计阈值；黑市商品以 `Math.min(3, …)` 截断。新增品质必须贯穿普通怪、精英、隐秘首领、商人、黑市、特殊事件、命运骰和宝箱，不允许只在测试存档里出现。现有 Boss 保底传说逻辑在前期应保留；后期不应该默认每个 Boss 都送当前最顶级档次。
- `compareEquipment/damageExpectation` 当前是**伤害/生存估计**，对条件效果、幸运和特定 Boss 的实际收益不可能完全准确。新稀有度与复杂遗物必须以真实战斗模拟回归其推荐可靠性，避免页面说“明显更强”却长期不如旧装备。

**房间、敌人与天赋：**

- [`src/encounters.js`](https://github.com/seiya058904/Dice-Abyss/blob/9acf0e0/src/encounters.js) `generateExpandedRoute`：普通 `combat` 在战斗抽取池中重复出现六次，其他解锁战斗类型大多各占一次；靠“当前层去重＋最近几次历史排除”控制重复。**现在不是显式的“核心/少见/罕见”三级加权机制**。如果继续给战斗池添加许多新房间，核心房的占比可能被稀释。
- `generateExpandedRoute` 的服务房由楼层模四轮换 `merchant / forge / fusion / rest`，最后一房固定精英（每五层固定 Boss）。这是有价值的节奏骨架，扩展时应继续保证**商店、锻造、融合等功能稳定可达**，但允许适度的权重变化和保底，避免机械可预测。
- 现有 `mystery` 房下只有八种主要模板事件，已有可拒绝、交易代价、永久加成上限和有条件出现的实现。下一轮可将**同一房间中的事件变体**扩得更丰富，不必每一种文案都创建独立房间键；新增独立房间必须有独立机制。
- [`src/content.js`](https://github.com/seiya058904/Dice-Abyss/blob/9acf0e0/src/content.js)：地牢主题名只有十个循环，60 个敌人中有重复的基础性状；新地区阶段需要能改变敌人/事件/奖励的真实分布，而非只换一个背景词。
- 天赋已分为高点、同点共鸣、暴击连锁、生存、幸运五路。`power` / `vitality` 的大级数上限负责长期成长，但普通节点多在中期满级；V5 应让**深层玩法带来新选择和协同**，而不是只有无限加百分比。

**规则、存档、页面、视觉与测试：**

- [`src/engine.js`](https://github.com/seiya058904/Dice-Abyss/blob/9acf0e0/src/engine.js) 的 `stats` 存在幸运 100、暴击/追击/闪避/减伤、部分词缀等上限。更高品质、三遗物和新天赋叠加时，可能较早碰到上限，使高级词条实际失效。应测量后校准，并在 UI 明示有效收益，不要盲目取消全部上限造成概率或数值失控。
- `GOLD_CAP=1e10`，金币达到上限时某些回收交易会被拒绝；背包上限 10,000，满包会保留未开奖励但暂时不能开箱。V5 需要复现这些边界组合，确保**清理背包、领取奖励、经济消费**不会互相卡死。
- [`src/storage.js`](https://github.com/seiya058904/Dice-Abyss/blob/9acf0e0/src/storage.js) 校验四档品质（经 `validEquipment`）、六房路线、房间和敌人键、五路天赋、事件类型、装备来源、版本和概率状态。增添新键必须同时更新校验与**V4→V5 迁移**，保留 V1–V4 导入与旧档归档，尤其是**已经生成但尚未打开的旧宝箱、旧商店商品、旧稀有度与 RNG**。
- [`src/app.js`](https://github.com/seiya058904/Dice-Abyss/blob/9acf0e0/src/app.js) 采用状态先提交再播动画；但开箱特效、融合保护、回收确认及声音仍有不少 `rarity===3` 和传说专用分支，必须扩展成按**品质阶层**统一驱动。禁止因为新增品质导致高级物品被安全批量回收。
- [`src/views.js`](https://github.com/seiya058904/Dice-Abyss/blob/9acf0e0/src/views.js) 负责绝大多数页面和物品卡，改动会影响五装备位、强度比较、天赋网、奖励揭晓及长背包。`talentEffect` 当前通过文字正则推算累计收益，新型机制节点应由真实规则数据派生展示，避免写着收益但结算不同。
- [`src/styles.css`](https://github.com/seiya058904/Dice-Abyss/blob/9acf0e0/src/styles.css)、`visual.css`、`expansion.css`、`rooms.css`、`polish.css`、`refinement.css`、`progression.css` 共七层 CSS。改动品质色、宝箱和新房间时统一其视觉语义；不能只在一个文件里新增颜色、被后续样式覆盖。
- [`src/effects.js`](https://github.com/seiya058904/Dice-Abyss/blob/9acf0e0/src/effects.js) 与骰子渲染对战斗 RNG 独立。保留已实现的倒角立体骰和特效缓存/裁剪策略。模拟 4K 仍有长帧，本轮新稀有度演出应**重点突出罕见瞬间、限制持续发光和全屏叠层**。
- `scripts/simulate.mjs` 的品质统计数组现在固定四档，且批量融合筛选 `rarity<3`；`tests/` 含 `13` 份测试文件，`scripts/audit-v4.mjs` 和 `luck-audit.mjs` 可复用。新增后的新档次出现分布、首次获得楼层、对战回合、经济闭环必须进入**可复现的自动化审计**，而非仅检查“新数组长度=8”。
- 新增 JS 文件需要同步 `package.json` 检查脚本；新增静态资源要在本地 `scripts/serve.mjs` 中可访问，若 ZIP 包含 Pages 工作流也应兼容其静态文件集合。保持已有的静态网页部署能力，但本轮无需实际部署，不要为内容扩展引入不必要的服务端或基础设施。

## 2. V5 的核心新增：分层解锁的八档稀有度

### 2.1 保留旧四档，在更深处继续长出新目标

**建议 V5 首轮实现八档，后续是否扩至九档按长期模拟决定。** 不是因为八是绝对正确数字，而是原有四档 + 四档阶段解锁已经能显著延长奖励追求，又不会立刻让字体/颜色/概率体系失控。

| 品质顺位 | 建议名称（允许提炼得更好） | 可掉落楼层 | 体验目标 |
|---|---|---|---|
| 1 | 普通 | 1 起 | 基础装备、融合材料 |
| 2 | 稀有 | 1 起 | 明显早期提升 |
| 3 | 史诗 | 1 起 | 有辨识度的优质奖励 |
| 4 | 传说 | 1 起 | **保留旧版金色品质、倍率与早期荣耀感** |
| 5 | 神话 | **第 30 层**起 | 第一次突破传说，开启深层新追求 |
| 6 | 太古 | **第 50 层**起 | 高级敌人与精英奖励开始值得进一步追求 |
| 7 | 起源 | **第 80 层**起 | 拓展稀有规则和构筑潜力 |
| 8 | 永恒 | **第 140 层**起（可依模拟调整） | 非常深层的顶级收藏与长期目标 |

名称和配色是美术候选，不要机械使用七彩闪光；仍以灰/蓝/紫/金为前四档基底，后四档各有清楚的标签、强调色、边框细节和出场仪式。无论多高品质，装备仍以文字和线框为主体，不制作武器/怪物插画。尤其不能通过降低传说的实际属性、价格或外观尊贵程度来“抬高”新档次。

### 2.2 概率与强度的硬约束

1. **第 1～29 层，维持 V4 原有四档的来源与稀有度分布。** 普通战、精英、Boss、秘藏、商店等分别核对；不能因新 `RARITIES` 数组增长，就悄悄稀释早期史诗/传说概率。第 5、10、15、20、25 层原有 Boss 必得传说的体验继续保留。
2. 到达解锁楼层时，新品质**才开始进入可抽取范围**，并从低概率起步；继续深入后逐渐提高可见机会。原四档仍有用途，不能所有掉落立即替换成最新品质。每个阶段结束前，玩家应该普遍有机会见到该阶段新档次，而不是只在百万分之一时才掉落。
3. 不同来源的概率各自合理：普通怪可以极低概率惊喜掉落；精英、隐藏 Boss、特殊秘藏、极稀有事件与黑市可以提供更好的追求或保底，但不能让每五层 Boss 立刻稳定发放“刚解锁的最高档次”。允许根据模拟设计渐进保底或深层奖池，但必须公开可信、不让玩家无限免费重投。
4. **相近 Lv. 与相近 +N 投入时，高一档品质明显更强**；等级增长则保证同档装备越刷越好。不同 Lv. 与极高强化投资可能出现例外，此时清晰显示真实强度比较。旧传说不会因为第 30 层出现“神话”就立刻被后台削弱。
5. 装备 `Lv.` 继续以人物等级附近浮动为主，深度决定品质解锁与遭遇奖池，**不恢复成长百分比或额外深度乘区**。融合只增加装备 Lv./经验，锻造只增加单件 +N；旧材料强化可以合理折算融合经验，但不自动转移 +N。
6. **140 层以后仍有持续成长空间**：不必无休止增设第九、第十品质，主要通过持续提高角色与装备等级、深层专有机制和新的挑战阶段获得更强装备。校验最大等级、数值安全、存档体积及显示格式，不要假装计算系统数学意义上无限大。

### 2.3 奖励体验与保护机制

- 高档掉落时，比旧传说**更有获得感**，但实际奖品必须真实入账；不用假卡牌填满概念图。普通开箱短促，高阶开箱仪式明显分层，点数、光效、声效、卡片和名称同步。
- 批量回收、快速融合和特殊交换**默认保护所有传说及以上品质**、已装备、锁定和待领物品；强制使用珍贵材料必须明确预览、再次确认。不能依靠 `rarity===3` 的旧判断误删更高品质。
- 新的装备名、词缀、属性和配色必须与品质一致，避免“神话装备只是紫装加了一个更亮标签”。至少有一批真正稀有的机制型高阶装备，在正常路线可以获得并触发。

## 3. 房间更丰富，但必须按“核心—特殊—罕见”分池加权

### 3.1 保持每层六房、战斗为主，先分配位置再按权重抽取

优先保留这个玩家已经熟悉的基本节奏：**三间日常/特殊战斗 + 一间稳定服务 + 一间事件/奖励 + 一间精英或 Boss 终点**。通常每层 **4/6 是战斗（约 67%）**，每五层的固定 Boss 仍然存在。不要改成《杀戮尖塔》式多分支选图，也不要单纯按 50 种房间统一随机。

核心机制改为**分层抽取**：先决定战斗/服务/事件槽，再在各槽自己的“常见池—特殊池—罕见池”里抽取，最后考虑楼层解锁、最近历史、主题、稀有度和保底。这样即使将来增加 100 种稀有事件，也不会挤掉玩家最需要的普通战斗和锻造。

| 槽位和层级 | 建议概率/约束 | 期望体验 |
|---|---|---|
| 战斗位：核心池 | 战斗抽选中**约 60%～75%** | 普通怪、基础特殊怪和容易读懂的精英变种是日常主力 |
| 战斗位：特色池 | **约 20%～35%** | 机制更特别的怪、环境战斗、连战、挑战任务，形成变化 |
| 战斗位：极罕见池 | **约 2%～8%** | 隐藏 Boss、特殊强敌、深渊异变；可以被记住，而不泛滥 |
| 服务位：核心服务保障 | **每层至少一间**，商人/锻造/融合/休整有周期上限或保底 | 玩家总能花金币、升级、整理成长，不会长时间抽不到必要服务 |
| 事件/奖励位：基础池 | **约 65%～80%** | 宝箱、黄金、祭坛、普通奖励、简单交换为主 |
| 事件/奖励位：特色池 | **约 15%～30%** | 有代价的协议、奇遇、临时规则、较特殊商人等 |
| 事件/奖励位：极罕见池 | **约 2%～7%** | 特殊祝福、稀有商人、远古遗藏、隐藏契约等记忆点 |
| 末房 | **每五层必有常规 Boss**；其他层优先精英，特殊终点受控 | 进度确定，隐藏 Boss 是惊喜而不是取代正常 Boss 的惩罚 |

这些区间是**策划目标，不是要求固定精确值**；由你用自然种子测试调校。注意表中的概率是在各自槽位**内部**，不是全局每间房都独立按这些数字抽取。低概率房间数量可以很多，但“稀有池总概率”不能随其成员数量无限上升。

**防重复与可达性：** 近几层避免重复相同特殊事件；珍稀 Boss 的触发有深度门槛与冷却；每个新房间至少在某个合理深度有真实自然出现概率；需要特定物品才能参与的交换，不应在条件不满足时反复刷到空白页面；无法接受任何交易时也能安全离开。请提供**实际分布统计**：总房间占比、每类权重、10/30/50/80/140/200 层的可达类型、隐藏首领出现率、各服务两次相遇的最长间隔。

### 3.2 内容扩充目标：不只加标题

建议从 30 类提升到 **约 45～60 类有意义的房间**。即使最终更多，也必须服从上面的权重结构。优先增加这些方向中的真正独特机制（名称和组合由你优化，不必逐项硬做）：

- **常见战斗与变种**：持盾精英、破甲试炼、猎手伏击、共鸣反制者、高点猎杀、低点诅咒、连续围攻、生命回复型强敌、特殊地形压力；有可读的弱点、危险预告和专门掉落倾向。
- **特色战斗**：追击挑战、精英双战、限定回合挑战、悬赏追猎、换取奖励的危险加成、以特定骰面击破防御的守卫、不同阶段的环境 Boss。
- **极罕见战斗**：隐藏 Boss、被遗忘的深渊君王、远古精英军团、特殊强敌契约；至少有有辨识度的机制与奖励，不是普通 Boss 改个名字。
- **核心成长服务**：普通商人、深层商人、锻造、融合、治疗/休整；实用房间出现稳定，且交易界面快捷明了。
- **有取舍的事件**：用少量生命换更好的宝箱、用旧装备换随机稀有掉落、支付金币换一次高风险骰奖、可选牺牲一件旧装备换永久小祝福、免费但条件严苛的挑战事件、稀有交易与可拒绝契约。玩家始终明确看到**代价、可能结果、奖励是否永久、拒绝选项**。

所有新房间都应有：**可辨认的规则或选择 → 实际发生的结果 → 合理奖励/风险 → 存档支持 → UI 文字及视觉反馈 → 能证明自然可达的测试**。不要把同一套“+10%攻击”改十个房名伪装成十个系统。

### 3.3 深度主题和敌人编排

可以为 1–29、30–49、50–79、80–139、140+ 等深度设计不同的章节氛围、敌人家族、事件倾向和高阶掉落。房间仍在一条线上，不需要真正的地图贴图。原有十个循环地名可保留为局部地点，但深层玩家应该能感觉进入了新的时期。

怪物目标建议从 60 个增加到 **约 90～130 个有名字、有机制归属的身份**，Boss 从 12 位增加到 **约 16～22 位**。不能只换血量和名字：给不同族群建立可读的特性、阶段、反击规律、骰面反制、专属奖励，并让新怪在不同深度确实自然出现。Boss 要有明显的阶段演出，同时强力玩家仍有可能依靠真正强大的构筑速杀，不人为让每场都强制拖七回合。

## 4. 装备、天赋、幸运与长期数值：更多，但必须更好懂

### 装备目录与定位

八档品质下，若旧 `216 件/类` 原样扩品质就已达到 **1,296 件**，这是**数量起点而不是最终内容贡献**。可以继续扩大到 **约 1,400～1,800 件甚至更多**，但前提是增加新主题、新名字、不同属性方向与可实际触发的能力。不要只靠“四档改八档”声称已完成内容大扩展。

必须保持三类装备的不可替代性：

- **武器**：主攻击、穿甲、高点、暴击伤害、首击与 Boss 终结，主要决定怎么打得更猛。
- **防具**：生命、防御、减伤、闪避、护盾、恢复、抵御特殊攻击，主要决定怎么活得更久。
- **遗物（三槽）**：幸运、特殊点数、共鸣、追加攻击、独特规则、经济掉落和情境变化。遗物应真正有组合价值，但不能普遍比武器更适合提供基础攻击、比防具更适合提供基础生存。

高档装备可以拥有简单、自动触发的罕见能力，例如“出现三同追加一次特殊回响”“六点攻击额外穿盾”“击败精英获得小额临时幸运”“同点触发护盾”“首次暴击使下一次掷骰更幸运”。**不要求玩家战斗中手动管理这些技能**。必须定义可测试的触发时机、次数上限、伤害口径和与当前道具的联动，不能产生无限连锁。让玩家看到珍贵掉落时大多能立即判断该不该换装，复杂流派仍可深挖。

### 天赋与幸运

现有五路三十节点基础已经可用，建议深化为 **五～六路、约 42～54 个节点**，或同等规模的内容更新。优先增加真正有差异的**高点、同点、暴击/追击、生存、幸运**及可选的**探索/战利品**路线。重点不是多一个按钮，而是让天赋的升级选择能显著影响投骰、额外触发、掉落和特定敌人应对。描述必须短、直接，最好一眼看明白“触发条件→获得什么”。

幸运必须继续影响高点和同点，但应核查现有幸运 100、共鸣引导与概率上限的边际收益；如果新遗物和天赋很多却让幸运早早封顶，新增词条将失去意义。不要简单放大概率直至必出六点，而应保留随机性，必要时让溢出的投资获得公开、合理的次级价值。所有概率在正常构筑和高幸运极端构筑下都应可重复验证。

### 长期经济和战斗节奏

- 以真实模拟分析 10 / 30 / 50 / 80 / 100 / 140 / 200 / 更深楼层的玩家攻击、怪物强度、装备更新频率、稀有度首次出现楼层、技能触发频率、Boss 回合数、金币存量与消费能力。
- 保留“**普通怪快、精英更有区别、Boss 有明显机制和演出**”的基本节奏；高战力玩家的爽感不能被暗中按装备战力追平的怪物数值抹掉。
- 长期金币不应只是撞上上限：可以有较少但有意义的高层金币用途（稀有商人、锻造、融合、特殊事件交易等），仍然**只有一种金币货币**，不引入新的碎片货币系统；保障满包、金币上限及本次奖励能继续合理处理。
- 装备等级、强化、稀有度的加成要共同形成持续增长，不能出现“新最高品质解锁，但因一个属性早已封顶，拿到之后实际毫无提升”。先校准可见收益再增加纯数值。
