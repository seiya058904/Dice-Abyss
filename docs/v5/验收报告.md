默认保护全部传说及以上、已装备、锁定和当前待领物品。特殊材料使用需要明确预览和确认；回收溢出金币需要再次明确同意，不暗中把高阶物品当普通材料消耗。

## 4. 路线权重、核心保障与可达性

路线骨架仍为三间日常战斗、一间服务、一间事件或奖励、一间精英或 Boss。每五层最后一间固定 Boss。连战、主动接受的挑战可以增加实际战斗场次，但不改变六个地图房间或增加选路。

首个战斗槽固定核心，后两个槽按 55% / 39% / 6% 选核心 / 特色 / 罕见，总目标约 70% / 26% / 4%。事件槽目标 73% / 23% / 4%。槽位选池后，再按成员权重、深度、区域倾向和历史抽样，因此加入更多稀有房间不会扩张稀有池总量。

商人、锻造、融合、休整四层一洗牌组，各出现一次。同一服务的最长间隔七层。新开局从第 1 层开始分组，V4 迁移从第一次 V5 路线开始新组，不修改已经生成的旧路线。隐藏首领共用至少八层间隔，不替换五层一次的正常 Boss。

满包编码约 2.17 MB（UTF-8）；浏览器存储通常还涉及主档、镜像和升级前备份。**本次没有测实际浏览器配额和写入耗时**，不能因为 Node 编解码成功就保证任何浏览器都能存下多份满包。额度写入失败测试验证了安全拒绝与保留旧档路径。

计时脚本的原 stdout 把 `performance.now()` 的毫秒差误标为秒；JSON 保留原始毫秒测量并换算成秒，脚本也已修正。这是统计单位修正，不是重新计时或性能承诺。

原审计变量记录 JavaScript 字符串 `.length`，报告已将误命名的 `maxSerializedBytes` 更正为 `maxSerializedCodeUnits`，不更改数字；真正字节数另见 `boundary-audit.json`。

## 7. 装备能力、天赋、敌人与比较结果

新增 15 个能力键均测试触发条件与真实结果：六点穿盾、三同回响、低血强敌终结、首掷与异点增伤；暴击 / 低点 / 换相护盾、六点恢复和低血减伤；遗物回响、首暴幸运、精英追星、六点金币与同点恢复。回响不会再暴击、追击或递归触发自身，单掷总回响有上限。

五路各三个新增天赋检查了楼层门槛、等级上限、元数据说明和实际结算。旧 30 节点继续保留，选中分支显示新节点，不把 45 个节点硬塞进旧星图导致规则入口丢失。

10 类新战斗、6 位新 Boss 的规则族通过真实伤害、穿盾、反击或保护结果对照，不只是检查名称数组长度。10 类新事件分别测试成本、拒绝、确认、只可结算一次、保存重载与真实奖励。没有物品参与条件时不会强迫玩家进入无法退出的交易。

首暴幸运的精确定义已写入词条：首次暴击后幸运增加，直到下一次战斗掷骰结束；离层或死亡重试清除。期间若有奖励或其他事务使用幸运，也可享受该临时数值。不是只修改一个骰面，也不是永久幸运。

### 比较器的已知局限与修复

以 256 个种子 / 装备方案、每场四次真实战斗掷骰，在普通敌人、厚盾和低血 Boss 三种构造场景中做 60 组比较，覆盖同级同强化与旧装备高投入两类条件。

**发现 4 组面板方向与厚盾生命伤害方向不一致。** 原因是换装丢失基础穿盾，原始伤害估算增长，却不保证短期打穿厚盾。已加入“穿盾需权衡”专用等级和前后穿盾百分比，移除这些情况下无条件的“明显提升”结论。

修后原始估算方向冲突仍是 4 组，但 **0 组缺少明确穿盾风险提示**。这是诚实标注估算边界，不是伪称把比较模型变成全敌人精确解。条件遗物仍标为估算；护盾恢复、经济收益、流派长期生存没有被该 60 组伤害试验全面排序验证。

## 8. 幸运统计

受控构筑为有效幸运 0、20、45、100 和极高投资构筑。每种抽取 200,000 次六骰，共 **1,000,000 次投掷、6,000,000 个骰面**。实际高点（5/6）比例约为 33.38%、44.47%、49.39%、53.31%、54.61%；三同及以上比例约为 36.74%、43.44%、50.31%、68.26%、69.12%。极端样本的有效幸运为 144，不是手写“必定六点”。

幸运超过 100 后按公开软增长增加有效幸运，最高 200；溢出投资另有最高 +50% 金币次级价值。所有样本的六个面均出现，存档重放的 RNG 结果一致。统计夹具不是自然得到该构筑的概率证明。

开箱、购买、融合、事件的重复动作拒绝与保存重载一致性有引擎 / 存储测试。**没有在浏览器 DOM 中实际按刷新键验收**，对此不作实玩通过声明。

**交付定位：可运行源码与规则验证完成的 V5 独立评审包；不是已发布线上版本，也不是已完成全部实机验收的最终发布结论。**
