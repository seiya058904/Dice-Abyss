# Round26 · 独立复审结论

本轮范围为 **v5.25.0 → v5.26.0** 的两处局部性能优化及历史运行基线恢复修复。独立审阅未发现新增 P0/P1；受控 CPU 收益成立，原生交互与帧时仍是混合结果，严格像素等价尚未证明。推荐在最终 ZIP 实体门槛完成后交付，并保留下列 P2 风险。

## 收益与必须保留的负面结果

万件标准袋三种排序的CPU样本均12/12对更快；强度/品质/等级p50分别7.197→2.040、6.502→4.430、7.890→5.187ms。计时每样本取10次选择均值，不是单次点击尾延迟；小袋和两处CPU尾部退步仍在PERFORMANCE。

骰子边界144轨迹/22,320供给帧的六字段严格相同；18,534帧证明可复用旧框，角点投影和三角函数减少73.04%。CPU整批p50 63.076→19.518ms、12对全更快。这是函数成本，不能写成真实显示帧或FPS同比提升。

原生万件背包固定12对，每格数值为 **p50 / p95 / max，单位ms**：

| 动作 | 输入 | 当前 | 快 / 慢 / 同 |
| --- | ---: | ---: | ---: |
| 打开 | 83.4 / 106.0 / 162.4 | 78.8 / 104.7 / 361.3 | 7 / 5 / 0 |
| 筛选 | 71.9 / 81.7 / 88.3 | 62.9 / 71.4 / 77.7 | 9 / 3 / 0 |
| 翻页 | 43.6 / 52.9 / 53.6 | 46.3 / 52.1 / 53.6 | 3 / 7 / 2 |

打开最慢当前pair6为首次RAF等待110.1ms＋两次RAF间隔251.2ms；没有足够证据将其归因于GPU、调度、GC或本轮某一改动。翻页p50升6.2%，不能写“所有背包操作更快”。原driver历史排除的回收区已由独立检查补上：两版参考串、78行原始HTML与每动作完整DOM均相同。

原生动画48主窗保留10,676个RAF间隔，14品质覆盖窗的3031个间隔另计。24对主窗p95按原始浮点为10快/14慢/0同，其中一对差仅约3.7e−9ms；显示到0.1ms时为10快/13慢/1同，两种口径均保留。8格p95中位5低/3高；1080永恒full三对均较慢，4K Boss full中位23.6→24.4ms。1080 Boss full、Boss low、永恒low最坏max分别454.9→501.6、469.4→669.1、687.3→788.8ms。整体最大值2604.7→862.3ms不能抵消这些退步，原生整体非劣性未证明。

## 严格像素与有界同版本诊断

初次跨版严格RGBA **5/7通过、2/7失败**：motion160为1像素/3通道，motion240为4像素/10通道，RGB最大差1、alpha不变。原判定和完整负证据保留，不能用几何、绘制计数或肉眼判断代替零容差结果。

随后预声明仅8对同版本诊断：motion160/240各2对输入自比和2对当前自比。功能全部通过、运行错误0，严格RGBA **2对通过/6对失败**；输入自比每场景1通过/1失败，当前自比每场景2失败。负例1–10像素，RGB最大差1，alpha全不变。这证明“源码版本不同”不是这些微差出现的必要条件，不能证明原跨版严格等价或根因已确定。历史Canvas1/18、GL2/7失败仍是另外的开放项；不合并样本抹平它们。

## 恢复与最终实体门槛

主控已真实复现：旧Round24恢复在`inventory-query.js`发生identity mismatch；旧Round25在`dice-renderer.js`发生oversized。回执归档于本轮`reconstruction/`。**唯一推荐入口为`restore-runtime-baseline-round26.py`**；`--round=24/25/26`分别重建v5.23.0/v5.24.0/v5.25.0。三轮verify-only＋新目录恢复共6调用通过，R26全部77文件还逐字比对真实上传基线；已有目录、项目内部路径和符号链接父目录3类输出均拒绝，无意外写入。

本文件不独自构成最终ZIP通过证明。本次独立复审未执行最终封包/fresh unzip；须由主控在最后重封后的准确实体上核验ZIP<50,000,000字节、展开≤100,000,000字节、CRC/路径/清单SHA、语法、声明的完整原生案例和HTTP启动，回执置于包外。最终状态以STATE、VERIFY和交付回执为准。物理GPU/4K60、实际设备、JS heap峰值、断电及历史4×400自然队列仍有未验收范围。
