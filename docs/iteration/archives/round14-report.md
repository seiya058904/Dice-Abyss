## 2. 基线诊断和范围决定

上一轮留下的受限构筑在第 30 层死亡，但原死亡页已有“可先打开背包换装”的提示和全局背包入口，所以不存在“原版死亡后禁止换装”的 Bug。本轮解决的是**复盘信息不足、既有选项不够直接、专用入口需要摆脱旧筛选**。

从相同完整失败终态，47 件武器、47 件防具、40 件遗物各对应三个替换槽，得到 214 条合法单件换装，加 1 条原装备控制，共 215 条分支。全部保留：**3 胜、212 死、0 预算耗尽、3,459 掷、0 花费**。这说明某些现有条件收益值得检查，不是通关率实验，不能据此调整全局难度。

另一项输入问题能直接复现：package／HTML 是 5.13.0，标题和页脚仍显示 5.12.0。新三项版本测试对输入为 1 通过、2 预期失败。

| 候选 | 决定与理由 |

## 3. 玩家得到的变化

- **看见刚才发生了什么。** 死亡页显示实际掷骰次数、敌人剩余／最大生命，以及最后一掷对生命的伤害和受到的反击；没有 lastRoll 时不虚构记录。
- **直接调整现有构筑。** 展示真实未装备数量、防具数量和可用天赋点。“调整防具”清空旧品质并定位防具；“打开背包”清空槽位与品质。普通背包导航继续保留玩家原筛选，导航不写主／镜像。
- **把敌方机制和条件收益放在准备旁边。** 回顾当前敌人的既有特性、换相和应对文案，引导查看已有“比较条件”。基础评分不会被当成存活保证，也不自动替玩家挑装或投入点数。
- **重试规则更明确。** 重试免费，按当时构筑补满生命并重新挑战当前敌人；装备、金币、天赋与完成房间保留。现有护盾与下一掷临时幸运不继承，开战护盾按构筑重新计算。服务仍需对应房间。
- **键盘与大小窗口可用。** 桌面焦点进入可见的当前天赋分支标题，窄屏进入分支 tabs；复盘在桌面舞台内滚动、窄屏随页面流动，4K 文本随现有比例扩大。
- **当前版本可辨认。** 标题、页脚、package 和 HTML 同为 5.14.0；新 release 模块与三项检查防止再次遗漏。产品版本与 schema5 分离。

原生实玩从保留死档经 i123 防具详情、换装、刷新、重试，**29 次手动按钮掷骰后胜出并开箱**；每一步与实际引擎的完整状态比对。该物品名称含“永恒”前缀，但实际品质为 3／传说，不是第 30 层提前掉落品质 7。详情见 [GAMEPLAY_REVIEW](GAMEPLAY_REVIEW.md)。

## 6. 性能：调用减少成立，响应改善未证明

52 个受控场景中，Canvas 完整命令、参数、尺寸、区域与生命周期一致，累计少 **49 次几何读取、29 次无必要 prepend**。这只是准备调用层面的改进。

原生固定时钟像素 18 场：**17 严格通过，1 个 4K 永恒存在两处边缘像素差异**。同基线源码两个上下文 A/A 的 3 次重复也出现相同差异，完整 RGBA 和 diff 保留；没有放宽为“全像素相同”。

普通正式性能在最终冻结源码执行：24 个背包正式样本＋2 预热、32 主帧窗＋14 品质窗。独立复算 57/57，before／after／HTTP 与最终源 **102/102 匹配**。共 5,424 RAF 间隔、61 条 >50 ms、6 Long Task、7 个预期 full 阶段未被观察。4K 永恒 full 最大间隔两次分别为输入 **2,688.1／9,662.6 ms**、当前 **9,273.6／4,776.1 ms**，没有稳定改善。
