# 性能复核 · Round19 / v5.19.0

结论：**MEASURED_WITH_LIMITATIONS**。本轮功能/布局有验证收益，但不宣称普遍提速或稳定FPS。万件背包默认打开的p50从137.1升至224.0ms，p95与最大值下降；部分full特效窗口明显更慢。所有正式样本保留，没有为好看的结果排除慢值或补跑替代。

## 环境与预定协议

本轮在全部模拟、默认/原生测试和其他浏览器任务结束后，以同一工作环境启动一个本地Chromium做A/B。Chromium 155.0.8059.84 / Playwright1.62.1 / Linux / DPR1，ANGLE Vulkan SwiftShader **软件渲染**。实测开始 2026-10-19T09:07:41.658Z，结束 2026-10-19T09:11:19.291Z，墙钟217.633秒。两loopback实际HTTP release和源码SHA均验证，前后源码不变，0运行错误。

沿用已审查的 `scripts/qa-performance-round.mjs`：1万装备、末尾5件已装备、60张首屏卡，在未选生存词条时通过主导航打开背包，交替baseline/after各12正式点击，另各1个预热；只排除这2个明确预热。计时从原生可信点击捕获到第二次requestAnimationFrame，协议传输不在该窗口。每次都核对所有60张完整卡片HTML，共92,909B，哈希一致；主档/镜像保持原字节。

两个origin都实际成功写入主档与镜像，每份2,060,957字符，未修改浏览器配额。基准不是保存耗时优化，也没有测出近上限真实私人存档的安全保证。

主矩阵是2场景（Boss暴发/永恒开箱）×2尺寸（1920×1080/3840×2160）×full/low×2版本，**16窗口，每格一次**。另对其余7品质在1920/full各版本1窗口，共14覆盖窗口，不能混入主矩阵或当作提速证明。场景为校验器接受的构造保存；六条180字符长日志按原上限，完整后态、镜像和随机过程都核对。

目标窗口4200ms，卡顿时实际窗口可以超出；测量Promise在原生click调用返回后再设置30秒等待上限，不能称为端到端动作保证。没有触发该deadline或自动重试。分位数取有序样本 `floor((n-1)*p)`；不截尾、不剔异常值、不挑最快窗口。

## 证据与边界

`evidence/round19/performance/performance-round.json.gz`保留全部24点击值、全部30个窗口的统计/长任务/像素峰值/效果标记观察、精确后态指纹、HTTP版本、环境和前后源码；`fixture-manifest.json`与原生成脚本可重放。**没有保留逐帧interval数组**，因此独立复核可重算库存分位数并核对窗口统计/公式，不能声称重新从逐帧原件计算了每个p95。

本轮没有改renderer、effects、演出时钟、装备卡HTML或保存实现。近5MB同步保存尾部、软件4K长帧和实体GPU复核继续是P2。功能收益是可找到真实生存候选、正确保持/重置上下文以及完整可读的卡片；不能据此抹掉本表负向性能结果。
