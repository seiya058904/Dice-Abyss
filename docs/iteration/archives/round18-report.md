## 2. 诊断与选择

上一轮明确留下的 pending silent_anvil 同 ID 引用，本轮用原始构造 envelope 复现：旧 validator 接受，事务先移除材料，再升级已脱离背包的同一对象，导致目标丢失；另有护甲/遗物被错误当作升级武器。正常事件入口会分别登记安全旧物与入场武器，因此这是**构造导入边界**，未证明自然事件经常吞装。

六类装备事件还依赖泛用问号和短付款文案，玩家要离开房间找材料。空名称又会被误判为不存在，部分展示按名称与金额字符串猜物品身份。导入失败主要靠短暂通知，重新选择同名文件和慢读取替换的衔接不足。这些问题有具体状态、低体积实现和明确复验方法，优先于增加内容表或重写保存/渲染。各领域候选、六个已访问来源和舍弃理由见 [RESEARCH.md](RESEARCH.md)。
