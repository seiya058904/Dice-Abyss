## 真实筛选历史与焦点合同

自然死亡档页面准确显示 **134 件未装备物品、47 件防具、0 个未用点**。每个当前自然视口都先通过旧背包实际选择武器及品质 7，得到真实空结果，然后回到死亡页。点击「调整防具」后品质筛选清空、槽位变为防具、分页重置，焦点到达可见的防具标签，背包呈现 48 件防具，包括正在装备的一件；「47 件可换」没有把当前穿戴物计算进去。

再次建立旧武器/品质筛选并返回复盘后，点击「打开背包」会同时清空槽位与品质，焦点到达「全部」标签。普通背包导航保留原先的筛选语义，只有带显式复盘重置标记的入口进行上述清除。所有这些视图导航前后，主档与镜像存档的原字符串均保持一致，完整玩法状态也保持一致。[原生逐步检查](evidence/round14/gameplay/browser-attempt-02/report.json)

「查看天赋」选择当前可见的已选分支控件：桌面为地图中的分支标题，窄屏为顶部标签。第一轮曾将桌面焦点交给隐藏的窄屏导航，失败时焦点仍在页脚入口；现通过 `!disabled` 与实际布局可见性选择目标，两类布局均有原生验证。0 点的自然样本只供查看；构造的 2 点样本实际投入 `power` 一次后，主/镜像、`power +1`、剩余 1 点、HP 0 和真实刷新后的状态均与引擎一致。

## i123：比较、换装、29 次原生掷骰到领取

1366×768 组在真实背包中打开 i123「永恒·破晓灵衣」的比较条件，核对其恢复说明与 **5% 再生**，按 Escape 回到原入口，存档原串不变。点击装备后仍处于死亡态 **HP 0**，金币和 RNG 均未改变；实际重载页面、继续旅程后仍回到这份复盘。它没有把换装误当成自动复活。

随后由原生「重燃余火」按钮启动战斗，驱动进行 **29 次独立按钮点击**。每一掷都等待真实结算与存档完成，再将完整状态与引擎的同一合法动作结果深比较；同时比较主档与镜像原串。最终从 `combat` 到 `chest`，再通过原生开箱到 `loot`，背包增加一件到 140 件；原有 21 次死亡没有被改写。报告保存所有 29 次实际 `lastRoll`、RNG、HP、敌方生命/护盾及各提交的完整状态指纹，开箱后完整状态另存。[逐掷记录](evidence/round14/gameplay/browser-attempt-02/report.json) · [完整 loot 状态](evidence/round14/gameplay/browser-attempt-02/native-rescue-loot.save.json)

这证明该存档、该装备和该动作序列可以经实际页面完成。它是离线确定性分支的原生界面复现，不是另一条从第一层开始的自然旅程，也不证明随机玩家都会选到这件装备或必然获胜。三个获胜防具与 212 个失败分支的审计口径见 [GAMEPLAY_REVIEW](GAMEPLAY_REVIEW.md)。

首轮 4K 说明仍固定为 12 px，在整页放大的框架中显得过小；修复限定于死亡复盘 CSS，以局部 rem 比例及窄窗像素下限兼顾两端。最终 4K 说明最小值为 26.85 px。选定原页面、首轮缺陷和最终页面由 [images.json](evidence/round14/gameplay/images.json) 索引；图片为实际截图缩放转码的小图，索引保留原 PNG 的尺寸、长度与 SHA256，不把它们当作原始像素等价证明。

从实际 pointer hover 和键盘焦点取得的计算颜色另做亮度比值计算。三个新入口中，「调整防具」hover 前景 `rgb(217,229,236)`、背景 `rgb(20,32,39)`，文字对比度 **12.934:1**；「打开背包」「查看天赋」hover 为白色同背景，**16.592:1**。焦点为可见 2 px 实线、`rgb(54,229,244)`，相对保守周边表面 `#202126` 为 **10.460:1**。复盘普通文字在同一表面界限下的最低值为 **8.455:1**。这些数值来自原生计算样式及 sRGB 公式，周边表面使用保守色值界限，未做逐像素焦点环覆盖率认证。[颜色数据与计算口径](evidence/round14/gameplay/visual-review-round14.json)

## 复跑与验收限制

从项目根目录配置本地 Chromium 和 Playwright 依赖路径，启动两版本地服务器后执行：

```sh
node scripts/qa-defeat-round14.mjs \
  --source /path/to/current \
  --baseline /path/to/baseline \
  --url http://127.0.0.1:4389/ \
  --baseline-url http://127.0.0.1:4388/ \
  --output /tmp/defeat-browser-round14
```

浏览器程序读取 `PLAYWRIGHT_MODULE` 与 `CHROMIUM_PATH` 环境变量。报告中的绝对截图/存档路径是原执行位置；可携带的包内记录由 [文件清单](evidence/round14/gameplay/files.json)和图片索引定位。两份原自然 JSON、原失败完整存档、全分支可恢复封装均在同一证据目录，具体复跑见玩法报告。

低特效和减少动态用于稳定完成实际页面行为；这组执行时间不能用于完整特效性能结论。逻辑视口及软件渲染也不等同实体手机、物理 4K 显示器或硬件 GPU。没有外部读屏、音效听测、触笔或操作系统挂起验收。既有核心页面、存档恢复、融合/天赋、renderer 生命周期与性能回归使用各自报告，由 [VERIFY](VERIFY.md) 与 [PERFORMANCE](PERFORMANCE.md) 登记；不与上述 11 组相加为自然玩家样本，也不据零运行错误推断所有设备都没有长帧。
