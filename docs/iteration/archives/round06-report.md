## 玩家实际得到什么

1. **超限的新存档不会覆盖现有活动档。** 输入只在读取时检查字符长度，新状态编码后直接写入；一个合法导入的合成档在掷命运后会超过自身可读范围。新入口先同时检查旧字符上限和5,000,000 UTF-8字节上限，再进行任何归档/主档/镜像写入。失败时保留原状态、RNG、金币、物品和可续玩存档，并提示先导出、再减少背包或检查额外导入数据。
2. **迁移导入先判定最终大小。** V4原档恰好5,000,000 bytes，增量迁移后的编码为5,000,337 bytes。现在在写旧档或当前档归档前拒绝，不会先消耗原生容量再失败。旧档decode、encode和精确导出救援未改，完整expected冲突检查仍优先。
3. **奉献祭坛与遗物织机准确说明已登记物品。** 玩家锁定、装备或保留了登记旧物时，界面显示那件物品的保护原因；合法空名称显示“未命名旧物（原ID）”。不会暗中另选背包中另一件物品，也不在打开确认框时扣钱。
4. **血井明确入井时记录的生命成本。** 换装增加或减少生命上限后，界面解释仍沿用入井的20%成本；必须保有严格多于该成本的当前生命。已有pending支付值及resolved结果均不变。
5. **记忆井付款前说明生命裁减。** 移除生命天赋可能降低当前HP，重新分配不会回满；说明进入真实选项和确认框。自然第159层样本在支付1,870金币时，HP由29,231降到23,385，符合既有规则；本轮修的是预告，不改平衡。

运行实现仅 `storage.js`、`encounters.js` 有逻辑/呈现变化；`views.js`仅两处版本标签，另统一package、HTML和README。36个原测试、1个fixture、53个原scripts、12个CSS和8个字体/许可文件逐字节保留。没有新增运行依赖、账号、货币、品质或位图资产。
