## 2. 诊断与选择

输入事件已经正确执行幸运偏骰、半价返还与品质门槛，但玩家必须自行把点数规则换算为概率、净支出和余款。这是值得新增的决策能力，不是原结算出错。实际确认的旧产品缺陷只有：界外许愿已有两颗结果骰，演出标题仍称“一颗”。新增 34 项原生测试在输入上 1 过、33 失败，其中 32 项属于缺少新能力，1 项对应数量文案缺陷。

候选审计还覆盖长期生存、预算策略、首次暴击语义、存档长尾及动效。没有证据支持扩一批同质内容或改平衡；dawnCrit 的“首次”需要先明确首次有资格与绝对首次的含义，保留 OPEN_SEMANTIC。[研究与方案比较](RESEARCH.md) · [玩法审计](GAMEPLAY_REVIEW.md) · [问题台账](BUG_LEDGER.md)

## 3. 玩家得到的变化

1. **付款前看清当前概率。** 命运赌桌展示三组单骰结果；界外许愿展示两颗独立愿骰总点数的三组结果。显示当前幸运，单骰 5/6 概率与两骰总点数分开说明。只计算公开规则，不读取下一次 RNG 结果。
2. **能算清本次花费。** 主表列出先付多少、整数退款、净支出与事件即时余额。例：付 835 金币后退款 417，净支出 418；宝箱金币在开箱时另结算。金币不足显示准确差额，不编造负余款；封顶 10,000,000,000 金币也能读完整。
3. **可以比较保底与宝箱品质。** 原生可展开表列出八品质条件概率与楼层门槛；赌桌保底单独按 2C 报价。早期固定品质与深层“至少某品质”的奖池保持原有区别。
4. **确认时仍看同一份账。** 选项卡给出净支出范围；付款确认显示当前所选模型及明确动作名称。键盘展开、取消焦点、配额写失败和跨标签复核沿用已有保护，真正提交仍只通过原事务。
5. **数量文案与实际一致。** 两颗愿骰演出称“两颗”，单骰仍称“一颗”；不增加或减少 RNG 消耗。
6. **减少新面板自身重复读取。** 一次页面 render 内为主表和选项共享 roll/safe 报价，公开模型仍每次读取当前状态，不跨状态缓存。12 个压力夹具完整 HTML 逐字不变；万件、30 层赌桌 HTML 构造 p50 从首实现 19.468 降为 12.407 ms，但仍高于同批输入 5.892 ms。

正常按六房间路线推进，遇到命运赌桌或界外许愿并处于未选择状态即可看到。没有增加入口、改变房间概率或解锁门槛；所有演示/压力存档均标为校验器接受的构造夹具，不能当成自然获得进度。
