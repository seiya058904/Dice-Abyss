## 3. 实际改动与故障关闭

**天赋投入与界面。** 从游戏底部进入“天赋”，选择 1／5／10／“当前节点最多”，再点一个节点。预览显示实际投入、前后等级、该节点贡献和余额；超余额／等级上限自动取合法数量。默认仍为原 +1，一次批量一次 revision；预览、数量、分支、悬停不写存档，不消耗 RNG、不治疗或复活。固定操作／预览区与可滚动节点区分开，保留焦点和位置；390px 按分支显示两列卡片。`engine.js`、`views.js`、`app.js` 与新 `talent.css` 为主要改动。

新增窄屏界面开发时曾继承旧星图 `:active` 位移，导致按下后卡片移动、mouseup 被外层截获。真实浏览器先复现，再取消该窄屏位移并修正圆环定位，最终 5 组／118 项通过，包含 390px 连续跨分支原生投入。没有强制点击或绕过命中机制。此开发失败和重测保留。

**奖励真值。** `content.js`／`encounters.js` 将赌桌、交换等支付前说明改为最低保证和深层可能性，结算读取已生成物品品质；旧 pending 档只修展示。6,160 个相同状态转移中 536 个结果文字改变，资产、宝箱、ID、RNG 和 revision 精确一致。护盾／穿盾解释与实际规则对齐。隐藏 Boss 的旧 runtime 覆盖已经正确，fallback 同步不计新玩家 Bug。

**S01 无效拍卖导入。** 原版接受“待决拍卖奖励 ID 已在背包”的合成档，后续购买无法持久化；原事务仍避免扣金，且可离开，所以不宣称自然生成坏档或玩家丢失资产。`storage.js` 在导入归档／替换前拒绝这种冲突，已解决历史仍接受。输入上的新增回归 1 失败／1 通过，当前全部通过；真实文件上传拒绝坏档且全部 localStorage 不变，合法对应档成功导入、购买、开箱。

**融合重复计算。** `fusion-workbench.js`／`fusion-controller.js`／`fusion-view.js` 及 `equipment.js` 的小范围调整，使普通选择不必排序全池，当前同步操作内复用模型，清空不必先做完整全选计划。控制操作可以不生成最终预览；真正显示和提交仍取权威预览。保留原排序后的经验相加顺序、最高六面安全判定和溢出时逐件跳过／补入逻辑，没有跨操作缓存。原 `fusion-dom.js`、融合 CSS 与骰子／特效实现保持原字节。

完整问题链、严重度及关闭方法见 [BUG_LEDGER.md](BUG_LEDGER.md)，语义与差分见 [FUSION_RULES_AND_PERFORMANCE.md](FUSION_RULES_AND_PERFORMANCE.md)。本轮新增 4 个测试文件，原 25 个均保留，没有删除或弱化既有断言；合计新增 21 项。

## 4. 玩法证据与兼容范围

旧 balanced 两种子各 400 层复现 41／50 次 Boss 长尾。同一自然战斗初态合法补完原优先级天赋后，相应长战为 2／1 次；不同构筑会改变后续 RNG 使用，不是相同全流程随机轨迹，也不是引擎提速。

手动最多六骰、每层六房、单金币、五装备位、八品质及 30／50／80／140 层门槛、目录 ID、schema 5 和存档键保留。默认单点 1800 个整状态差分、批量与旧重复投入 540 个玩家状态差分、12 类事务故障，以及 11 个 V4 夹具迁移编码逐字一致。完整快照比较、Web Locks、主／镜像保存、启明星痕 nextLuck 与历史反击／护盾保护继续有回归覆盖。
