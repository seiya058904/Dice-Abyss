## 2. 为什么选择这轮范围

从既有非预知 luck/adventurous 策略实际走到 200 层，得到第 4 层付费幸运、第 49 层护幕储备、第 62 层回声首掷状态。原左栏“探索增益”只有路线概况，实际储备要靠旧日志记忆。第 62 层真实初态中，开战前有/无回声的基线战斗 HTML 相同，但相同骰面 `[6,6,6,1,5,6]` 的实际总伤害相差 **657,652**。这是收益确有作用却难确认的可复现信息缺口，不是伤害引擎失效。

六个既有扩展首领也只有原短机制标签，没有当前/下回合战术面板。确定事件的金币、生命、等级与护盾裁减则值得在不可逆选择前明确。相对新增内容表、重写同步保存、未经物理 GPU 支持的渲染优化，本轮选取这些有自然证据且不改变交易语义的改进。研究、未选候选及各领域审查见 [RESEARCH.md](RESEARCH.md)。

## 6. 性能：真实测量、有明确限制

Chromium 155.0.8059.84、Linux、DPR1、ANGLE/Vulkan **SwiftShader 软件渲染**。新旧各 12 次万件背包原生点击，共 24 正式行；每侧只排除预先声明的一次热身，60 张卡片完整 HTML 相同且读页面不改档。下秩 p50 为 137.2→89.1 ms，p95 252.8→222.2 ms，**max 326.8→382.5 ms 变差**。样本有限且最大值方向相反，未改库存选择器，不宣称背包优化成功。

另有 16 主窗口（2 版本×1920/3840×Boss/永恒开箱×full/low）及 14 个普通至神话开箱覆盖窗口；每格一次，4200 ms 目标窗口，不丢长帧。4K 最大 rAF 间隔输入 **11,110.8 ms**，当前 **9,624.3 ms**；三个 full/4K 窗口未观察完整预期 FX（输入一个、当前两个）。这既不能证明稳定60 FPS，也不能把没有 Long Task 条目当没有卡顿。详细正负格、分位定义与事务检查见 [PERFORMANCE.md](PERFORMANCE.md)。
