## 2. 诊断、取舍与改动

原 storage listener 忽略 `localStorage.clear()` 的 `key=null`，也未即时处理主档/镜像均缺失或不可读。输入页仍保有可导出的内存，后续 expected 保存会拒绝；本轮修复的是**及时反馈、旧内存的持续保护和可判断的恢复入口**，不能称作已证明新磁盘档被旧页覆盖。

| 方向 | 收益与证据 | 决定 |
| --- | --- | --- |
| 跨标签丢失/重建后的进度保护 | 输入可重复出现，原生事件与 VM 都可验证；接力上一轮明确开放项 | 主目标，完成 |
| 骰体索引复用 | 属性展开可逐字比较，原几何重复上传可精确计量，风险局限于 renderer | 完成，不改视觉预算 |
| 软件 4K 开箱长帧 | 确有长帧，但计时环境为 SwiftShader，开箱窗口中骰子像素为 0 | 重新测量并保留开放，不能归因给本轮骰体 |
| 深层 Boss/构筑与消费 | 四自然种子发现真实受限策略失败，样本并不证明引擎错误 | 完成诊断，不改难度、RNG或价格 |
| 新房间、装备、叙事扩编 | 没有优先于当前保护问题的可验证机制设计 | 推迟，未用列表扩容冒充内容 |
| 生成背景/装饰图 | 不能解释存档选择，会增加资源和遮挡 | 实际采用代码原生恢复版式，未调用生图 |

修改运行文件：`index.html`、`package.json`、`src/app.js`、`src/storage.js`、`src/dice-renderer.js`；新增 `src/save-recovery-view.js` 和 `src/save-recovery.css`。运行源码按 index/package/src（排除 fonts）统一口径从 927,613 增至 945,756 字节，净增 **18,143 字节**。没有新增运行依赖、字体、音频、位图或动画循环。来源研究见 [RESEARCH](RESEARCH.md)。

## 3. 玩家可见结果与故障关闭

- **即时保留本页旅程。** 另一同源标签清空、删除两份记录或写入不可读记录时，显示恢复页，保留完整最后已提交内存，取消旧确认、未完成导入和演出回调，阻止继续交易。已提交的掷骰结果不重掷，未知字段不丢弃。
- **可选择、可核对的恢复。** 页内显示楼层、等级、金币、掷骰与旅程标识，可先导出完整内存，再重新检查。只有主档和镜像真实为 `null/null`，且在现有 Web Lock 内再次确认后，才可明确重建；有任何原串或锁内新进度就拒绝覆盖。
- **浏览器已有进度另行读取。** 新存档出现时保留旧内存，展示候选摘要；确认读取前允许再导出旧页，读取时逐原串复核，成功读取不写磁盘。损坏的原串可以另存原始记录，明确标为非正常导入文件。
- **重复通知保留交互。** 通知检查时一直可读到相同完整状态，保留当前设置/待确认/动画；同 ID 和 revision 但未知字段不同仍视为不同进度。若跨标签并发时真实观察到双份暂缺，则进入持续保护，后来同数据返回也需显式读取。
- **骰子几何更轻。** 5,184 个重复属性顶点改为 1,014 顶点与 5,184 个 Uint16 索引；相同 1,728 个三角形、完整 Float32 属性与顺序保持。上传合计 **186,624 → 46,872 字节，减少 74.88%**。这不是整个 GPU 内存或 FPS 的降幅。

新事件 12 例对输入为 3 通过/9 个预期失败；候选曾为 9 通过/3 失败，独立审计发现 clear 后立即创建另一进度仍会切走旧内存，补丁后全部通过。恢复存储 17 例与事件 12 例共 29/29；独立 25 原串组合＋4 组附加矩阵通过。详见 [SAVE_RECOVERY](SAVE_RECOVERY.md) 和 [BUG_LEDGER](BUG_LEDGER.md)。

## 5. 性能结论的范围

Node 几何准备 8 对预热、60 对正式样本：p50 **2.893 → 0.414 ms**，p95 3.983 → 0.648 ms；仅构造静态网格的 CPU 微基准。

实际 Chromium 155.0.8059.84 / ANGLE Vulkan SwiftShader，24 背包正式样本＋2 预热，32 主窗口＋14 品质补充窗口。背包 p50 150.9 → 112.2 ms，但 12 对为 6 快/6 慢，完整 DOM 相同，**不能宣称背包提速**。4K 永恒 full 两对最大 RAF 分别为输入 3,000.3/6,015.9 ms、候选 **9,660.2/8,673.4 ms**；候选两窗均未观察到最终 loot-7。

主矩阵 full 各观察 5/8，共 6 窗缺阶段；1080p 八品质各 8/8。5,422 RAF、55 条超过 50 ms 的间隔、2 条 Long Task 均保留。16 个永恒窗口的骰子像素峰都为 0，因此不能把这些开箱长帧归因于索引骰体。OPEN-PERF-01 保持开放。

正式计时针对**测量候选**。最终随后只改了 app 的 storage listener 和恢复页 primary 配色，96 身份条目有 94 相同、2 个声明差异；57 项离线核验通过，但最终身份仍为 `DIFFERENT_DECLARED`。候选文件体未独立保留，最终补丁和字节差不能替代完整历史差分。路径不进入该矩阵是源码/平台语义推论，不是原报告实测事件数。最后版本另外完成原生恢复、像素与生命周期验证。详见 [PERFORMANCE](PERFORMANCE.md)。
