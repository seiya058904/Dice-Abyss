#### 是否阻断保留终帧修复

**复审建议：保留局部工作量修复，帧尾部风险保持 OPEN_RISK；不追加 A/A、不通过重跑选择绿色结果。**该建议不是“没有回退”的判定。

源码和已声明夹具动作表明，修改后的 `animateDice` callback 只在 full、非 reduced-motion 且 `ui.rolling || ui.forging` 时执行；`app.js` 只让 roll / fate 设置 rolling，让 forge / fuse / bless 设置 forging，明确不含 open。因此 **6 / 8 主 cell 不经过本轮修改的提交分支**：四个 eternal-open cell 加两个 boss low cell。这 6 个 cell 的最坏值同样退步。此处是源码路径分析，不冒称新增 profiler 的覆盖记录。

终帧时刻是投掷经过 1,280 ms 后，记录中的主要长间隔常从点击后约 180–900 ms 开始；4K 的秒级空隙大多没有能解释其长度的已观察 long task。原报告没有存下终帧实际提交时刻、完整图形队列或另一个 context 的工作，因此不能把负面尾部归因于终帧修复，也不能证明该修复对调度绝无影响。renderer 与全部 CSS 均与基线逐字相同；shader 候选已经撤回，无法作为解释最终结果所必需的变化。

保留的理由是：源码明确删除了同一终帧立即被覆盖的一轮绘制，真实 GL 计数在两种尺寸均给出 12 → 6；最终静止预算、尺寸、时间线和提交状态保留，原生生命周期功能回归通过。当前风险不足以建立“这几行终帧修复导致整个矩阵退步”的因果关系，故不凭未隔离的数据回滚一个已证明减少工作量的局部修复。与此同时，8 / 8 最坏值退步、9 个未采到预期 FX 的窗口和严格 RGBA 失败均作为未关闭风险保留，不能用 CPU 收益抵消它们。A/A 只能描述同源码变动范围，单独也不能替这项变化排除或建立因果关系；本轮没有执行新的 A/A。
