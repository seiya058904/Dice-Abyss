## 结论与范围

当时被测候选仅修改运行文件 `src/inventory-query.js`。过滤、分页前选择、三种排序、非法 sort 的强度回退、原对象／原数组、稳定相等顺序、旧合法稀疏属性和未知字段保持。强度排序每候选只估值一次；品质／等级排序只在主键相等时估值，并在本次临时行内复用。没有跨调用缓存，没有物品 ID 去重，没有改动伤害、掉落、品质、回收或保存逻辑。该排序实现最终没有发布。

万件混合 fixture 的三种排序在本次 Node 采样中缩短；简单顺序有分配代价，完整负向见下表。**这只是过滤与排序函数的 Node 时间，不能据此称浏览器打开速度、paint、FPS 或 GPU 性能改善，更不能关闭历史软件 4K 秒级长帧风险。** 浏览器脚本由根代理执行，本代理没有控制浏览器。

## 正确性与边界

- 21 个最终 benchmark 场景均验证完整输出顺序、原对象引用和原输入不变；63 次后置 variant 计数也执行相同核对并恢复属性描述符。
- 新增 `inventory-sort-cost.test.mjs` **7/7**；原 `inventory-search.test.mjs` **7/7**。默认 Node `--test` 输出的两个文件 wrapper 不等于 14 个细项；细项由逐文件直接运行核对。
- 万件 mixed 的 itemValue 次数：power **178,930→10,000**；rarity **119,812→10,000**；level **137,276→9,997**。读取次数直接观察已哈希 `itemValue` 每次必经的单次 enhance 访问。空／单件／无结果／主等级全部不同都保留 0 次。
- 另有源码探针发现 `stats()` 两轮重复 find／itemStats；根代理决定暂缓。`engine.js`、`equipment.js` 最终与输入 SHA 相同。此前背包卡片已改用仅已装备集合的 comparisonState，不能再写成每卡扫描完整万件背包或声称本轮消除了平方级路径。

## 错误尝试与不利候选保留

- `initial-instrumentation-before-timing.mjs/.json/.stdout.json`：计数 getter 虽然恢复描述符，仍可能改变 V8 对象形状和内联缓存；该份时序明确 **INVALID_FOR_TIMING**。解释留在 `initial-instrumentation-before-timing-limit.json`，不能用该报告异常大的基线时长计算提升。此修正来自测量方法错误，未删除或替换慢样本。
- `generic-lazy-inventory-query.js` 与 `generic-lazy-sort-benchmark.json`：计数时序修正后，通用动态属性／回调比较器真实使万件 rarity p50 2.8256→3.6362、level 3.4695→4.0922 ms 变慢。这份负向原样保留；最终改为静态命名比较器后才产生当前报告。
- `source-audit.mjs/.json`：实现前独立隔离排序／stats 候选及同源码 control，3 规模各 48 个组合的完整 gameView HTML 和完整 state 相等；该实验不是最终版本，也不包含真实浏览器。stats 候选没有进入工作源码。
