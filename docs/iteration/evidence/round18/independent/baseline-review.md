# Round 18 独立只读审计：基线发现

基线：`baseline/Dice-Abyss`，输入包版本 5.17.0。未改运行代码、已有测试、已有文档。此阶段只做代码阅读与真实引擎的构造存档复现，没有声明自然出现频率，也没有把 Node 生成 HTML 当作浏览器实际点击。

## 可复现问题

| 编号 | 问题 | 基线结果 | 建议边界 |
|---|---|---|---|
| IA-01 | `silent_anvil` 的 `offerId` 与 `targetId` 相同 | 合法存档可编码、解码；选择可确认；背包 7→6，升级目标永久消失；结果仍通过保存校验。预览仅返回 null，不会阻止交易。 | 禁止消费目标自身，choices 与 apply 共用检查；原始记录应保全，安全离开可用。 |
| IA-02 | `hollow_scale` / `silent_anvil` 的登记目标不是武器 | 分别将 targetId 指向护甲或遗物，4 个构造例均可确认且保存有效；页面及结果仍称武器。 | 检查登记对象实际 `slot==='weapon'`，不能改为必须等于当前装备位。 |
| IA-03 | 未命名旧物被说成不存在 / 确认框丢失详情 | exchange、relic_exchange、silent_anvil 的 `name=''` 是有效物品，消费可成功，但 cost/confirm 写“已不存在的装备”。offering/relicloom 已回退为未命名物品，但 5 类选择均因 `choice.cost===offer.name` 不成立而丢失确认框的等级、强化、经验详情。 | 区分对象不存在与名称为空；以明确消费选择和登记 ID 判断详情，不用显示字符串判断身份；不回写物品名称。 |

复现文件：`reproduce-event-ui.mjs` / `baseline-event-ui.json`，共 16 个构造输入。

IA-01 对应 `src/encounters.js` 的 silent_anvil choice 与 settlement；`src/event-preview.js` 对相同 ID 只隐藏预览。IA-02 对应 `eventChoices` 中两事件仅检查目标存在；预览继续按目标属性计算。IA-03 对应 `src/encounters.js` 的 `itemName`，以及 `src/views.js` 事件代价详情、`src/app.js` 事件确认详情中的文本相等判断。

## 必须保留的正常行为

- 入场登记武器之后换装，仍升级原登记武器，不能偷偷替换成现在的武器。
- 对原登记目标加锁只保护其不被消费，不应禁止它接受升级；两事件“换装后再锁定原目标”的控制样例均正常。
- 材料已装备、锁定、被删除等状态不能被另一个可用材料替代。
- 所有 16 个输入均能安全离开，玩家资产与 RNG 不变。
- 数组型 targetId 如 `["i1"]` 被旧正则隐式转字符串接受，实际严格 ID 匹配不到，交易不可用。该现象不是额外资产损失，但应在引用类型校验中明确处理，不可将它强制转换成真实 ID。

## 导入与确认路径

`app.js` 在显示导入确认前调用 `decodeSave`；真正写入前，`saveImportedGame` 再验证完整存档、原始 envelope、当前磁盘快照及最终容量。原始归档写入发生在这些检查之后。

事件确认经 `act` → `transition` 重新查询 `eventChoices`。另一窗口的有效进度变更会清除 pending 并关闭对话框；写入前也检查 state identity 与磁盘完整快照。此次未发现需要重写确认权限流程的新漏洞。

增长最明显的是 round15 证据：512 文件、13.85 MB 解压、1.91 MB ZIP。较大的 round14 证据压缩后 2.05 MB。脚本全部压缩后约 0.57 MB；清理它们对 50 MB 交付预算收益有限。

对 docs/scripts/output 做 SHA-256 完全一致内容去重，发现 42 组，共计最多节省 **1,681,147 解压 bytes**；ZIP 收益更小。主要重复是相同 DOM 快照及相同模拟结果，不能由哈希相同推断旧执行没有价值：需要保留各次运行的命令、日期、根目录、结果与该哈希的关系。

建议本轮不做历史清理：目前距离 50 MB 还有超过 22 MB，先控制新证据的数量。后续若要压缩，可为完全一致的大 DOM/JSON 使用一份内容对象与逐轮索引；保留失败、阻塞、原始存档、版本迁移、关键验收与完整测试的证据链。

`output/playwright` 的历史截图已压为 WebP，被 README 与集成验收文档多处引用，不宜直接删除。最大的源文件是离线中文字体约 8 MB；它有实际离线阅读用途与许可文件，不能当测试垃圾删除。详细数字与重复组见 `package-growth.json`。
