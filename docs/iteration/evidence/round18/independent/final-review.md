# Round 18 独立复审结论

## 结论

**本次独立代码、存档、交易与 HTML 展示复审通过。** 基线发现的同一物品既作材料又作目标、非武器升级目标、空名称错误说明与确认详情缺失，均在修复后得到针对性验证。未发现本次改动导致正常登记装备、保护变化、历史存档或未知元数据丢失的新问题。

复审期间没有修改游戏运行代码、已有测试或历史文档。本报告只覆盖本线程亲自执行的范围；浏览器点击、布局、焦点和文件选择行为由主线程的浏览器验收另行记录。

## 1. 基线问题复现与修复后结果

`reproduce-event-ui.mjs` 使用实际引擎、实际校验器和存档 envelope，先对不可变基线执行，再对工作版本执行。16 个构造样例添加了顶层、event、每件 item 的嵌套未知字段。

| 样例 | 基线 | 修复后 |
|---|---|---|
| anvil 的材料 ID 等于目标 ID | 可导入、可提交、可保存；目标丢失 | 读入明确拒绝；直接 accept 返回原对象；目标与未知字段不动 |
| hollow_scale / anvil 的目标指向护甲或遗物，4 例 | 可提交并错误升级非武器 | 读入拒绝；accept 不改资产 |
| 两事件的数组型 targetId，2 例 | 旧正则接受，但交易不可用 | 引用类型明确拒绝，不把数组转换为真正物品 ID |
| 两事件登记武器换装后锁定，2 例 | 正常升级原武器 | 正常行为保持，仍升级原登记武器 |
| 五类消费事件的 offer.name 为空，5 例 | 部分写成“已不存在”，确认物品详情消失 | 不再误说不存在，仍按真实 ID 识别和消费 |
| 材料名称为“无” | 合法资产 | 合法性、资产与 RNG 行为保持 |

所有 16 例的安全离开均保留玩家资产与 RNG。所有执行后的保留对象均完整保留未知嵌套字段。对被拒绝的构造状态，afterValid=false 反映返回的仍是未经修改的旧畸形对象，不能误解为提交了新的无效存档。

证据：

- `baseline-event-ui.json`：首次独立发现。
- `paired-event-ui-baseline.json` / `paired-event-ui-current.json`：同一复现器与未知字段控制的配对结果。

## 4. 导入与确认的静态复审

原有 decode-before-confirm、提交时完整快照验证、写锁和归档时机均保留。

首次复审指出：若只在 change 时增加读取世代，用户再次打开文件选择器时，旧异步读取仍可能抢先替换设置对话框。主线程已修改为在打开新 chooser 时就作废旧读取，并将先前的“正在检查”状态改为“已取消上次检查”。另外，change 捕获 File 后立即清空 input.value，让同路径文件可再次选择；读取结束还检查世代、dialog.open 与原 input 仍属于该 dialog。

这些边界静态阅读已通过。是否焦点恢复、原生文件选择器行为与移动布局符合预期，依赖另行的浏览器验收，不能由本报告替代。

没有压缩或删除任何历史内容。输入包为 27,916,890 bytes，距 50 MB 预算仍有超过 22 MB。大部分脚本和原始 JSON 已能被 ZIP 有效压缩；清理对交付收益有限。历史截图已有引用、中文字体有离线用途，建议保留。
