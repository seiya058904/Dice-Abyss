# Round15 存档与大背包审计

## 已落地：确认回收批次不再逐件遍历整个背包

基线 `src/engine.js` 的 `salvagePreview` 在传入显式 IDs 时执行 `ids.map(id => items.find(...))`。背包“回收安全旧装”的确认回调会传入预览的完整 IDs；`transition` 的合法性判断与实际结算又各进行一次预览。于是一次合法的批量操作会重复进行两轮 O(背包数 × 回收数) 的查找。

修复仅在显式多件批次内建立一次 ID 索引；单件保持原来的 `find`。索引遇到重复 ID 保留第一个对象，返回对象顺序仍按玩家先前确认的 IDs；不缓存跨操作状态。实际删除路径原本已使用 `Set.has`，无需改变。

### 确定性来源与结果

从基线 `newGame(27017)` 生成完整、可通过 schema5 验证的合成万件背包；带有根部及单件未知嵌套元数据、锁定物品、五件已穿装备。数据不来自用户真实存档。

| 场景 | 背包数 | 确认件数 | 旧版一次预览读取 item.id | 当前一次预览读取 item.id |
|---|---:|---:|---:|---:|
| 小批次，普通/稀有混合 | 100 | 93 | 5,091 | 386 |
| 中批次，普通/稀有混合 | 1,000 | 971 | 490,120 | 3,942 |
| 万件，八品质混合 | 10,000 | 2,438 | 12,199,814 | 24,876 |
| 万件，普通/稀有混合 | 10,000 | 9,752 | 48,808,996 | 39,504 |
| 万件，单件回收 | 10,000 | 1 | 10,002 | 10,002 |

读取计数包含保护判断；原始 `find` 的索引遍历次数分别为万件混合 12,194,938 次、万件低阶 48,789,492 次。源码中的一次 `transition` 会做两次对应预览。这里的确定性次数不等于毫秒、输入延迟或帧率。

### 语义保护

新回归覆盖请求顺序、原始对象引用、完整输入不变、非法/重复/丢失 ID、已装备/锁定/本次战利品保护、珍贵装备确认、金币溢出确认、万件结算、存档镜像/重载、重复交易拒绝、余下装备完整未知字段与 detached clone。新测试 6/6；相同测试指向基线 5/6，唯一失败为二次方读取量。

`salvage-verify-only.json` 的五个场景逐一核对新旧完整预览、结算状态、输出包络、主/镜像写序、重载结果和调用方不变。没有删装备、改价格、改金币规则、改变存档校验、换用摘要 expected 或放松事务保护。

## 存档链发现但本轮未改动

普通提交仍有三次完整状态 `JSON.stringify` 和一次包络序列化：current、expected、新状态 payload，以及 envelope。可研究只在本次同步加载中保留已验证 V5 原 payload，先与完整 expected 字符串比对；不等时仍回退完整 current 字符串，旧版迁移保留旧路径。这能减少规范当前档的一次完整 stringify，同时保留非规范 JSON 与未知字段语义。本轮没有实施，以免同时改变安全存档链。

测量所用带未知字段的万件混合档为 2,658,900 UTF-8 字节 / 2,507,998 UTF-16 code units；内存 Map 存储可写双份并精确读回。此结果不等价于真实浏览器配额充分。5 MB 文件边界、后续增长、原存档、完整 expected、Web Locks、先验证再归档、主写失败与镜像失败语义均未修改。

## 证据及重跑

- `baseline-diagnosis.json`、`diagnose.mjs`：原始根因发现、计数、序列化诊断；`--verify-only`，无计时。
- `baseline-salvage-regression.tap`、`current-salvage-regression.tap`：同一新增回归的旧版红灯和当前通过。
- `salvage-verify-only.json`：工作副本真实模块的完整差分与 ID 读取计数。
- 项目内 `scripts/benchmark-salvage-round15.mjs`：可重跑纯验证或交替顺序的成对 Node 计时。

正式基准在主代理协调的 CPU 窗口完成：15格×8对正式样本、每格2对预热，共240正式样本和60预热。完整输出在 `salvage-paired-node.json`，独立逐项重算在 `salvage-node-review.json`，摘要及限制在 `salvage-node-review.md`。所有正负样本均保留，不以测试运行时间替代性能结论。特别保留计数前后 descriptor 改动可能影响 V8 对象形态、n=8 时 p95 等于 max、Map 存储不等于浏览器持久化的限制；本轮未追加 Node 采样。
