## 已确认的新问题

### SAVE-SIZE-ROUND06：存档写入与读回/文件导入大小边界不闭合

状态：CONFIRMED-SYNTHETIC。优先级建议 P1，具体严重度由整合者结合实际浏览器复验判定；不能称普通万件背包自然丢档已复现。

- 源码：`src/storage.js` 的 `encodeSave()` 只做结构验证，没有检查最终输出长度；`decodeSave()` 拒绝超过 5,000,000 个 JS 字符的字符串；`src/app.js` 导入文件却以 5,000,000 字节为上限。
- 合成输入：`newGame(77613)`，固定 runId，加入结构验证允许保留的 ASCII 扩展字段 `auditPadding`，使最终 UTF-8 导出长度恰好为 4,999,900 字节（4,999,835 个 JS 字符）。输入通过 validator、decode、app 文件大小门禁与实际 `saveImportedGame()`。
- 一次 `fate` 操作后：结构仍合法，编码长度为 5,000,642 个字符 / 5,000,724 字节；`saveGame()` 返回 `{mirrored:true,warning:''}`，两个活动存档均被替换，但 `loadSave()` 返回 `state:null`。
- 影响：写接口可能把自身读取接口拒绝的内容报告为成功；导出文件限制使用不同单位，还可能产生可读取但不能通过应用文件导入的导出件。
- 范围：在无配额限制的内存存储上确认。浏览器 localStorage 配额可能先拦截写入，需独立实测，不能据此宣称真实浏览器已发生双份丢档。
- 推荐最小处理：在任何归档及活动存档写入前，对最终编码结果检查新的写入边界，同时覆盖读回字符上限与应用文件导入的 UTF-8 字节上限；安全拒绝时保留既有两份活动存档。不应静默截断、清除扩展字段或关闭结构/快照校验。为兼容旧档救援，可以保留历史 `decodeSave()` 的读取能力，不必机械收紧它的边界。
- 正向对照：同种子普通 10,000 件自然生成装备为 2,039,228 字符 / 2,190,126 UTF-8 字节，完整往返通过；本缺口不是“万件背包一定超过限制”。

## 源码审阅结论与适用边界

### 主写、镜像及导入事务

`saveGame()` 在提交前读取持久化快照并完整比较；相同 runId/revision、资产不同的分支也拒绝覆盖。主存档写失败抛出错误；镜像写在主写后执行，镜像失败返回明确的“主档已保存”告警。应用只在主写成功后把内存 state 改为 after，因此不会把失败交易当成成功展示。需要保留此顺序，不能以性能为由跳过读回、结构校验、快照比较。

导入首先验证导入对象和原始封套一致、核对 expected，再优先归档实际可读的旧主档/镜像。旧归档不可覆盖，v1–v4 迁移保留 RNG、已有路线、敌人、商店与未领取奖励。既有 closure 审计确认 11 个 V4 fixture 往返与后续操作闭合。

### 重复点击及待领取奖励

应用 `committing` 与 `ui.busy` 双重阻止重复交易；确认弹窗点击后先清空 pending。引擎对已出售商品、已领取宝箱、已完成事件返回原对象。待领取奖励提前分配装备 ID，读取时检查已经发号、未拥有的奖励与商店碰撞；本轮 save-closure 实际覆盖事件/商店动作及重复动作，未发现新反例。

同源现代浏览器的 Web Locks 包住“读取/transition/保存”临界区。无 Web Locks 的兼容分支只剩同步快照比较，跨进程同时读写并非原子操作；这属于已有适用限制，不能声称所有旧浏览器已具备同等跨标签页互斥，也不把未实测竞争推测升级为已确认 Bug。

### 万件背包性能

10,000 件输入可以合法编码与解码，但这不代表实际浏览器完整交易低延迟。`transition()` 克隆完整对象，持久化侧包含完整 decode/validate、expected JSON 全量比较、encode/validate、主写与镜像写；页面绘制仍需选择、统计、排序。单次探针测得的编码耗时只用于说明规模和验证过程，不是正式性能提升结果。

此审阅未使用浏览器，未独立测真实 localStorage 配额、浏览器标签页互斥、物理断电、Windows 双击启动或 GPU 帧率。最终验收必须使用主控的相应浏览器/打包证据，并说明环境限制。
