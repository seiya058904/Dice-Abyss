# Round 12 条件装备比较：独立只读复审

## 结论

当前审核的 `equipment-comparison.js` 与 `equipmentComparisonView` 没有发现未解决的阻断问题。首次源码检查发现两个诊断/表达问题，已同时告知作者与父任务；作者修正后，独立执行的 **10 组检查全部通过**。

本任务没有编辑作者的运行代码。所有检查使用真实目录装备和可通过存档校验的构造状态，不属于自然生存样本，也不是浏览器/实体设备认证。

## 两个已解决问题

1. **基础宝箱金币封顶写错。** 最初比较模块用 100% 判断基础 `goldBonus` 封顶；实际 `engine.stats` 先对全部 `*Bonus` 字段执行 60% 截断，因此后面的 `caps.goldBonus = 1` 不会使基础值升回 100%。作者已把只读诊断改为实际 60%，没有修改引擎。独立实测使用原始金币词条分别为 25% 与 40% 的两个候选，加上另外两件 40% 遗物：两构筑生效基础金币都为 60%，用真实 `createChest` 生成的完整宝箱相同，金币均为 **787**。
2. **“六点穿盾合计”范围不清。** 原名称容易被理解为当前敌人的最终穿盾；实际还会叠加 `combatModifiers` 的遭遇穿盾。作者现用“含6穿盾 / 装备与天赋合计；遭遇加成另计”。独立铠卫变体 1 实测：装备与天赋贡献 **15.5%**，加遭遇 **60%** 后实战穿盾为 **75.5%**。真实掷骰总伤害 17,947、护盾吸收 4,397、生命伤害 13,550，与该最终值的取整一致。

首次源码观察先于冻结副本保存。`initial-equipment-comparison.js` 捕获时作者已完成上述两点修正，不能把它称为两个旧问题的可执行失败基线；当前报告已明确记录这一时间范围。

## 独立夹具纠正

第一次独立 probe 有两个失败，来自检查者没有显式指定遗物替换位。`relic2`、`relic3` 为空时，原 `equipSlot` 会正确填入空位，旧遗物不会被卸下；该 fixture 不适合断言旧词条消失。现已对比较与真实 equip 同时明确传入 `slot: 'relic'`。初轮报告保留在 `first-probe-fixture-mismatch.json`，不计产品缺陷，也不改引擎默认选位规则。

## 文件与复跑

- `review.mjs`：独立检查脚本。
- `current-review.json`：当前 10 组通过结果、场景数值和实际源文件 SHA-256。
- `initial-source-hashes.json` 与 `initial-equipment-comparison.js`：第一次保存副本时的来源记录，保存时间在作者修正之后。
- `first-probe-fixture-mismatch.json`：保留的独立夹具错误记录。

```bash
node docs/iteration/evidence/round12/independent-comparison/review.mjs /path/to/Dice-Abyss /tmp/independent-comparison.json
```

脚本与 `initial-equipment-comparison.js` 需置于同一目录；执行只读项目，在指定输出路径写报告。报告中的运行文件指纹属于工作树检查，最终 ZIP 解包后验证由发布任务另行执行。

包内脚本默认从自身位置向上解析项目根；省略输出参数时写入系统临时目录的 `dice-abyss-independent-comparison-review.json`，不会覆盖已记录的 `current-review.json`。仅默认路径适配为随包形式，10 组检查逻辑与原结果保持原样。
