## Confirmed findings

| Priority | Evidence and impact | Resolution |
| --- | --- | --- |
| P2 | `storage.js` evaluated default `storage = localStorage` before its read/write guards. A throwing getter interrupted `app.js` startup with an empty `#app`. A queued storage event also accessed the property outside a guard after permission revocation. | Defer property access to the existing guarded operations, and guard the event's storage-area comparison. Keep the real storage receiver, current permission checks, complete snapshot validation and primary-before-mirror contract. Never create a volatile replacement save. |
| P2 | README and the V5.27 summary still described PR #3 as unmerged and production as V5.26 after GitHub recorded its merge and successful deployment. | Correct the current status and explicitly label the earlier acceptance/publication descriptions as historical. Preserve their measurements and failures. |

The [HTML Standard's localStorage getter contract](https://html.spec.whatwg.org/multipage/webstorage.html#dom-localstorage-dev)
permits `SecurityError` when policy prevents persistence. Reproduction used an
isolated Chromium context with that getter failure injected; it does not claim
that a particular browser preference was changed. Before the fix the page
emitted `SecurityError` and rendered no app content. Two Node regressions also
failed on the original source, then passed on the fix.
